# Third Eye Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and deploy Third Eye — a daily-fortune PWA that combines seven divination methods (tarot, runes, I Ching, Western sun sign, Chinese zodiac, numerology, blood type), computed by deterministic code and interpreted by Claude in one of three oracle personas — on the S2 homelab behind Authentik.

**Architecture:** pnpm TypeScript monorepo cloned from Plantry's conventions (`D:\code\plantry`): Fastify 5 + Prisma backend, React/Vite/RTK Query/Tailwind PWA served by Caddy which proxies `/api/*`. A pure package `@third-eye/divination` draws and computes all results; the backend persists draws immediately (fortune `PENDING`), then interprets them with Claude structured outputs in the background while the frontend plays a ritual animation over the real draws and polls until `READY`. PostgreSQL only (sessions included); no Redis, no worker.

**Tech Stack:** Node 20, pnpm 10.33.2, TypeScript 5.6, Fastify 5, Prisma 5.22, zod 3, openid-client 5, `@anthropic-ai/sdk` (latest), tsup, Vitest 2, React 18, react-router-dom 6, Redux Toolkit 2 (RTK Query), Tailwind 3, `motion` (Framer Motion, `motion/react`), vite-plugin-pwa, Caddy 2.

**Spec:** `docs/superpowers/specs/2026-09-26-third-eye-design.md` — read it (including the two *Amendment* notes) before starting any task.

**Reference implementation:** `D:\code\plantry`. Several tasks say "port from Plantry" and then give the full code anyway; the Plantry file is there if you want to see surrounding context.

## Global Constraints

- Package scope `@third-eye/*`: `@third-eye/backend`, `@third-eye/frontend`, `@third-eye/shared`, `@third-eye/divination`.
- `@third-eye/divination` is **pure**: no Node built-ins, no I/O, no DB, no network, no `Date.now()`/`Math.random()`. Randomness only through the injected `Rng`. It is imported by both backend and frontend.
- API JSON is **camelCase**. Success responses are `{ "data": ... }`; errors are `{ "error": { "code", "message", "details"? } }`.
- Error codes (exact strings): `validation_error` 400, `unauthorized` 401, `forbidden` 403, `not_found` 404, `needs_onboarding` 409, `rate_limited` 429, `internal` 500.
- A fortune id that is not a UUID, doesn't exist, or belongs to another user → **404 `not_found`**.
- Cookies: session `third_eye_sid` (HttpOnly, SameSite=Lax, Secure in prod, 7-day sliding); OIDC state `third_eye_oidc` (signed, path `/api/auth`, 10 min).
- Mutating requests (non-GET/HEAD/OPTIONS) must carry `Origin` equal to `FRONTEND_ORIGIN` → else 403 `forbidden`.
- Env names: `DATABASE_URL`, `SESSION_SECRET`, `SESSION_COOKIE_SECURE`, `FRONTEND_ORIGIN`, `AUTHENTIK_ISSUER_URL`, `AUTHENTIK_CLIENT_ID`, `AUTHENTIK_CLIENT_SECRET`, `AUTHENTIK_REDIRECT_URI`, `AUTHENTIK_ADMIN_GROUP` (default `third-eye-admins`), `ANTHROPIC_API_KEY` (**required** — backend refuses to start without it), `ANTHROPIC_MODEL` (default `claude-sonnet-5`), `TRUST_PROXY_HOPS`, `AUTH_DEV_BYPASS`, `TZ`, `PORT`.
- Dates without time (birth date, fortune date) are `YYYY-MM-DD` strings everywhere outside Prisma. In Prisma they are `@db.Date` columns written as `new Date(`${d}T00:00:00.000Z`)` and read back with `.toISOString().slice(0, 10)` — use `toDbDate` / `fromDbDate` from `apps/backend/src/lib/dates.ts`, never ad-hoc conversions.
- "Today" for a user = `localDate(now, user.timeZone)` (`apps/backend/src/lib/dates.ts`).
- Fortune draws are **never re-rolled** once persisted. Retries only redo the interpretation.
- Logs contain user subs and fortune ids only — never birth date, name, blood type, prompt text or model output.
- Backend tests run against real PostgreSQL (`third_eye_test` on `localhost:5435`), single-threaded; `resetDatabase()` in `beforeEach`. Test DB URL must end in `_test` or the setup file throws.
- No test ever calls the real Anthropic API. The backend talks to Claude only through the `OracleClient` interface; tests use `FakeOracleClient`.
- Relative imports in `apps/backend`, `packages/shared` and `packages/divination` use `.js` extensions (NodeNext).
- TDD: write the failing test, watch it fail, implement, watch it pass, commit. One commit per task minimum. Commit trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Commands are run from the repo root (`D:\code\third-eye`) in Git Bash unless a step says otherwise. Use `corepack pnpm …` if plain `pnpm` is not on PATH.
- No Redis, no worker container, no licensed artwork (tarot faces are SVG drawn in code).

## Cross-Task Interfaces (locked)

These names and shapes are used across parts. Implementers of later tasks rely on them exactly.

```ts
// @third-eye/divination — types.ts
export type Rng = (maxExclusive: number) => number;            // integer in [0, maxExclusive)
export type BloodType = 'A' | 'B' | 'AB' | 'O';
export const METHODS = ['TAROT', 'RUNE', 'ICHING', 'WESTERN', 'CHINESE', 'NUMEROLOGY', 'BLOODTYPE'] as const;
export type Method = (typeof METHODS)[number];
export interface Profile { birthDate: string; fullName: string | null; bloodType: BloodType | null }
export type TarotPosition = 'situation' | 'challenge' | 'advice';
export interface TarotData { cards: { id: string; reversed: boolean; position: TarotPosition }[] }
export interface RuneData { id: string; reversed: boolean }
export interface IChingData { lines: (6 | 7 | 8 | 9)[]; primary: number; changingLines: number[]; relating: number | null }
export interface WesternData { sign: ZodiacSignId }
export interface ChineseData { animal: ChineseAnimalId; element: ChineseElementId; polarity: 'yin' | 'yang'; lunarYear: number }
export interface NumerologyData { lifePath: number; expression: number | null }
export interface BloodTypeData { type: BloodType }
export type MethodResult =
  | { method: 'TAROT'; data: TarotData } | { method: 'RUNE'; data: RuneData } | { method: 'ICHING'; data: IChingData }
  | { method: 'WESTERN'; data: WesternData } | { method: 'CHINESE'; data: ChineseData }
  | { method: 'NUMEROLOGY'; data: NumerologyData } | { method: 'BLOODTYPE'; data: BloodTypeData };
export type MethodData = MethodResult['data'];

// functions
castAll(profile: Profile, rng: Rng): MethodResult[]           // METHODS order, methods lacking input omitted
describeResult(r: MethodResult): ResultDescription            // { method; title; facts: string[] }
seededRng(seed: number): Rng
METHOD_LABELS: Record<Method, string>

// @third-eye/shared
export const PERSONA_IDS = ['MYSTIC', 'CONFIDANT', 'TRICKSTER'] as const; export type PersonaId = ...;
export const PERSONAS: Record<PersonaId, { name: string; tagline: string; sampleLine: string }>;
export interface MeDto { user: { sub; name; email; isAdmin }; profile: ProfileDto; onboarded: boolean }
export interface ProfileDto { birthDate: string | null; fullName: string | null; bloodType: BloodType | null; timeZone: string; persona: PersonaId }
export const profileUpdateSchema  // zod; all fields optional
export type FortuneStatus = 'PENDING' | 'READY' | 'FAILED';
export interface FortuneResultDto { method: Method; data: MethodData; reading: string | null }
export interface FortuneDto { id; date; status: FortuneStatus; persona: PersonaId; summary: string | null; results: FortuneResultDto[] }
export interface TodayDto { fortune: FortuneDto; fresh: boolean }
export interface FortuneSummaryDto { id; date; status; persona; excerpt: string | null; results: FortuneResultDto[] }
export interface FortunePageDto { items: FortuneSummaryDto[]; nextCursor: string | null }

// apps/backend
interface OracleClient { complete(req: OracleRequest): Promise<OracleResponse> }   // src/oracle/types.ts (impl: client.ts)
interface OracleRequest { system: string; user: string; schema: Record<string, unknown> }
interface OracleResponse { text: string; model: string; stopReason: string | null }
createOracle(deps: { prisma; client: OracleClient; log: FastifyBaseLogger }): Oracle   // src/oracle/interpret.ts
interface Oracle { interpret(fortuneId: string): Promise<void> }                       // never rejects
createFortuneService(deps: FortuneServiceDeps): FortuneService                         // src/fortunes/service.ts
```
